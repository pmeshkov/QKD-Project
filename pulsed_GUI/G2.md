# Pulsed / CW g2

Open the usual launcher and select **Pulsed / CW g2**. This records CH1 and CH2 together, then correlates every detector pair within the chosen delay range. With the current QKD PBS wiring, the result is **PBS-output polarization-resolved cross-correlation**. It is not automatically an unconditional source HBT g² measurement. Record the polarization settings and optical path in Notes.

## First recording

1. Close UniHarp and any other program using the PicoHarp. Stop programs owning Ctr0 if using the NI clock, or AO0/AO1 if enabling static EOM control.
2. In **Run**, choose the laser source and recording duration (default 60 s). Select **Check settings**, then click Run for an offline check. Select **Record** and click Run to acquire.
3. For **NI external**, the program generates PFI12 laser triggers at the selected 500 kHz–1 MHz rate. It waits for warm-up before recording. The default is 500 kHz, 100 ns trigger width and 1 s warm-up.
4. For internal **2, 20 or 80 MHz**, manually disconnect PFI12 from the laser, select that rate on the controller, and confirm the change in the GUI. **Pulsed external source (manual)** supports another externally supplied rate from 500 kHz to 80 MHz; this program does not generate that clock.
5. For **CW (manual laser)**, manually select CW and disconnect PFI12. No NI clock is generated. If BDL TRG OUT continues to pulse, disconnect it from PicoHarp SYNC for this mode. A substantial SYNC count rate causes the CW acquisition to refuse recording.

**Voltages:** optional static Alice/Bob EOM control defaults to No. Enable it to hold explicitly entered target voltages during acquisition; both outputs return to zero on exit. These are static measurements, with no pulse-by-pulse EOM switching.

**PicoHarp:** review the inherited polarization-profile settings. Both detector edges should be rising, with +200 mV thresholds; SYNC is falling with your working negative threshold. CH2's +4.5 ns hardware offset is applied once, not reapplied in correlation. Saved settings take precedence over defaults.

Recording progress appears in the log. Analysis starts automatically after acquisition, and the resulting preview is available through the GUI's plot button. This version does not show a live coincidence plot during recording. A short run checks communication; low coincidence rates may require substantially longer measurements than the 60 s default.

## Timing modes and analysis controls

Pulsed acquisition uses **T3**, storing the excitation-cycle index and photon delay after SYNC. CW uses **T2**, storing independent photon times without requiring an excitation clock. Overflow records are retained and decoded in both modes. Correlation lag can span many excitation cycles; it is not limited to the within-cycle arrival-time window.

The shared T3 configuration checks that its microtime range covers one laser period. At 500 kHz the period is 2 µs; 64 ps resolution covers approximately 2.097 µs. A narrower correlation bin cannot recover resolution finer than the recorded timestamps.

In **Analysis**:

| Setting | Meaning / default |
| --- | --- |
| Correlation ±half-range | 0 automatically includes the selected side peaks: ±12 µs at 500 kHz, ±3 µs at 2 MHz, ±75 ns at 80 MHz; CW defaults to ±2 µs |
| Correlation bin width | 2 ns initially; choose a finer bin for narrow peaks if counts and recorded resolution permit |
| Pulsed central-peak position | 0 ns initially; positions the integration windows if a residual relative delay remains; does not shift the recorded timestamps |
| Pulsed peak-area ±half-width | 0 selects 0.4 periods on each side; all peaks use the same bin-quantized width |
| Reference side-peak indices | Both positive and negative indices 2 through 5 |
| Offline arrival gate | Off by default; optionally accepts photons from either detector within a specified time after SYNC; pulsed only |

Pulsed results report the central integrated peak area divided by the mean selected side-peak area, with a finite-record exposure correction. This is an operational peak-area ratio. Choose side peaks that represent an uncorrelated reference; blinking, bunching, overlapping decay tails and background can affect it. There is no automatic background subtraction, decay-tail deconvolution or confidence interval. Gates change the measured quantity and are saved with the result.

CW results normalize pair counts by the product of the measured detector rates and bin-integrated overlapping acquisition time. This assumes stationary intensities. Inspect the count trace for drift. A zero reference count produces an undefined result, not a claimed zero g².

The preview contains three plots:

1. Raw CH1–CH2 pair counts versus delay (CH2 time minus CH1 time).
2. Pulsed: relative integrated area for each pulse separation. CW: normalized cross-correlation versus delay.
3. CH1 and CH2 count rates versus acquisition time, after any selected offline gate.

## Files and reanalysis

Recordings go to `data/g2/<UTC timestamp>/` by default:

- `metadata.json`: source, geometry, input settings, actual duration, device flags and acquisition status.
- `events.t3raw` or `events.t2raw`: complete ungated little-endian 32-bit raw TTTR records, including overflow records. These are not PTU files; keep the metadata with them.
- `analysis/<UTC timestamp>/g2.png`: preview.
- The same analysis folder contains `correlation.csv`, `count_trace.csv`, `analysis.json`, and pulsed `peak_areas.csv`.

Select **Analyze saved run**, choose the recording folder containing `metadata.json`, adjust Analysis settings, then click Run. Each analysis creates a new folder. This action needs no hardware and currently accepts recordings from this dedicated mode only.

All records are analyzed, using chunked reads and temporary disk-backed photon arrays rather than a prefix of the run. Allow temporary disk space of roughly eight bytes per retained photon in addition to the four-byte raw records. The default computation limit is 50 million photon pairs and the histogram limit is two million bins. Exceeding a limit stops analysis with an explanation rather than reporting a truncated curve; narrow the range or increase the configurable pair limit and reanalyze.

Stop during acquisition preserves raw data but marks the recording incomplete; normal analysis refuses incomplete or device-error runs. Stop during analysis preserves a previously completed raw recording for later reanalysis. Keep the log if acquisition fails.

Implementation is covered by synthetic correlation and simulated-device tests. Actual PicoHarp/NI streaming and optical behavior still require a bench run. T2 record decoding follows [PicoQuant's GenericT2 example](https://github.com/PicoQuant/PicoQuant-Time-Tagged-File-Format-Demos/blob/master/PTU/C/ptudemo.cc); timing modes are described in the [PicoHarp 330 manual](https://downloads.picoquant.com/manuals/PicoHarp330_Manual.pdf).
