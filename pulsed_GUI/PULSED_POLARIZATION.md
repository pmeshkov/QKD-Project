# Pulsed polarization baseline

Run `launch.py` and choose **Pulsed polarization**, or open
`pulsed_polarization.py` with VS Code's Run Python File button. No terminal
parameters are needed. Opening the window and **Check settings** do not access
hardware. This tool holds each Alice/Bob voltage pair constant while recording:
eight settings, two detectors each, sixteen arrival histograms.

## First run

1. Close UniHarp, the scope timing script, and other programs controlling AO0,
   AO1 or Ctr0. Wiring: AO0 = Alice, AO1 = Bob, BDL TRG OUT = PicoHarp SYNC,
   PBS detectors = CH1 and CH2.
2. Choose **NI external**, **500000 Hz**, and your tested trigger high time
   (default 100 ns). This program owns Ctr0/PFI12 and keeps the clock running
   across all eight settings. Do not run the separate clock GUI alongside it.
   Alternatively choose **Laser internal** and enter **2000000**, **20000000**,
   or **80000000 Hz**. Manually disconnect PFI12 from the BDL and select that
   internal laser setting, then set the form's confirmation to **Yes**. Software
   does not switch the laser mode. Measured SYNC must agree within 5%.
3. Check the six voltages. Defaults copy your reported Alice array
   `[-152, -50.87, 50.90, 152.69]` V and Bob `[47.52, -47.44]` V.
   These are EOM target volts; the DAQ receives **-target/20**.
4. Leave **Alice labels = Voltage index only** initially. S0/S1/S2/S3 follow
   notebook array order. The fit generates quarter-cycle steps: entries 0/2
   are one opposite-state pair, 1/3 the other. It does not establish physical
   H/V/R/L labels or circular handedness. Its array order is not H,V,R,L.
   Once identified, choose **Assigned H/V/R/L** and label each entry.
   Bob fields use nominal H/V and R/L labels; exchange the values if the
   physical basis assignment is reversed.
5. Detector outcomes can remain **Unassigned**; columns then say HV/CH1,
   HV/CH2, RL/CH1 and RL/CH2. Once measured, specify CH1's outcome in each
   basis; CH2 takes the other outcome.
6. Select each input's rising/falling edge to match the working UniHarp setup.
   Threshold defaults: SYNC -250 mV, CH1/CH2 +200 mV. Channel offsets: SYNC 0 ns,
   CH1 0 ns, CH2 **+4.5 ns**. All are editable. Edge mode is used.
   The code programs the offsets through PH330Lib in picoseconds and logs
   the requested values; these are not measured readbacks. Confirm the two
   arrival curves align. Analysis applies no second offset.
7. Start with **10 seconds per setting**, **1 second warm-up**, **100 ms static
   settling pause**, **Gate = No**. Select **Check settings**, click Run, then
   select **Record** and click Run. Allow about 80 seconds plus setup/pauses.
   Increase recording time for your low-count measurements.

The 1200 ns switching delay is not needed here: each voltage pair is held
throughout a recording, following the much longer static settling pause.
Photons during voltage changes and warm-up are not recorded into a block.
Software timing is sufficient between these static blocks; individual laser
pulses are generated by hardware and no absolute excitation index is claimed.

## Data and plots

Sessions save under `data/polarization/<UTC timestamp>/`:

- `session.json`: voltages, labels, acquisition order, raw-data paths, settings,
  completion status and cleanup results.
- `01_Alice_..._Bob_.../` through `08_.../`: each contains a timestamped recording
  with `events.t3raw` and `metadata.json`. Keep them together. This is raw
  GenericT3, not a PTU file.
- `analysis/<timestamp>/arrival_histograms.png`: sixteen ungated arrival curves;
  Alice settings in rows and Bob outcomes in columns. Axes share scales.
- `analysis/<timestamp>/polarization_matrix.png`: left, counts per second;
  right, detector counts divided by the sum of both detectors at the same
  Alice/Bob setting. Each **pair** of probabilities sums to one, not the row.
- The analysis folder also contains `counts.csv`, `ungated_counts.csv`,
  `rates.csv`, `probabilities.csv`, `cells.csv` (exposures/provenance),
  `arrival_histograms.csv`, `arrival_histograms.npz`, and `analysis.json`.
  Native-bin histograms are retained; the NPZ includes an `available` mask
  distinguishing missing measurements from measured zero counts.

The log reports both photon totals after each setting. Plots are made after
acquisition, not live. **Open plot** shows the matrix; **Open data folder**
opens the session folder. Find the arrival plot inside `analysis`.
For sparse curves, increase display rebinning or reduce **Plot end after SYNC**.
These display settings do not change native histograms or raw events.

## Change gates later

Choose **Analyze saved run**, select the folder containing `session.json`,
optionally enable a gate, and click Run. Acquisition fields are ignored.
All raw events are read in bounded chunks. Gates select quantized timestamps
`start <= time < end`, without interpolation. Each analysis creates a new
directory, preserving previous gate comparisons. Raw events remain ungated.

Stop retains partial data and marks an unfinished block incomplete. The code
attempts to stop its external clock, zero both AOs and release its tasks.
An internal laser remains under manual control. No device reset is performed.
Completed blocks of an interrupted session can be analyzed; missing cells show
N/A. Zero-count blocks have zero rates and undefined (N/A) probabilities.
Data-loss flags, truncated raw files and invalid SYNC cause errors.

Matrices are observed count ratios without background subtraction or efficiency
correction. They are not tomography, a secure key calculation or proof of pulse
alignment. Compare later switched measurements with a baseline at the same
source operating conditions; high excitation rates may change source behavior.

SDK reference: [PH330Lib manual](https://downloads.picoquant.com/manuals/PicoHarp330_DLL_Manual.pdf).
`polarization_analysis.py` is the supporting offline module; launch
`pulsed_polarization.py` for the GUI.
