# Pulse-by-pulse acquisition

Use **Ordered BB84** first, then **Randomized BB84** after the timing and optical tests. Both are available in the main launcher. Existing settings under the old names are inherited. These modes acquire commissioning data; neither establishes the absolute NI-to-PicoHarp trial origin yet.

## Controls

1. **Run:** select **Check settings**. Start with 1 second of experimental data and 1 second of warm-up using **500 kHz / 1200 ns**. The alternative scope-tested profile requests 750 kHz / 900 ns; integer timing realizes approximately 751,880 Hz. **Custom** unlocks rate and delay. Pulse width defaults to 100 ns.
2. **Voltages:** verify Alice H/V/R/L and Bob H/V and R/L targets. New profiles inherit voltages and PicoHarp inputs from the saved polarization form when available. Unassigned notebook entries use provisional opposite pairs 0/2 and 1/3; they do not prove physical labels. Confirm the physical states and Bob basis mapping experimentally before setting the confirmation to Yes. DAQ volts = target EOM volts / -20.
3. **PicoHarp:** review trigger modes, edges, thresholds, offsets, serial and binning. CH2 +4.5 ns is configured once in hardware; do not repeat that correction offline.
4. **Files:** choose the run directory and enter calibration/emitter notes.
5. For an actual measurement, choose **Record** directly: it prepares the complete sequence, saves it, then controls NI and PicoHarp. Everything for that acquisition is in one timestamped folder. **Prepare only (offline test; not used by Record)** is an optional, independent test of sequence generation. Its `_prepared` folder is not loaded by Record. A randomized Record generates fresh choices, so combining those separate folders would misleadingly mix two different sequences.

Use NI external triggering for these modes. Close other AO/counter tools and UniHarp. Opening the form or using Check settings does not access instruments. The new finite streaming acquisition requires bench testing; the earlier scope test used a repeating waveform.

The current physical chain is **NI PFI12 → externally triggered function generator
→ BDL SYNC IN**, with BDL TRG OUT connected to PicoHarp SYNC. The GUI trigger-width
field controls PFI12 only; the function-generator output width is set manually.
Its model, output width and delay can be recorded in the Run tab. These notes do
not configure that instrument. Confirm one laser/SYNC pulse per NI trigger.
Acquisition controls are disabled during Analyze saved run, and analysis controls
are disabled during acquisition/preparation, to distinguish the two workflows.

## What is generated

During warm-up, Alice holds H and Bob holds H/V. The experimental sequence begins at NI sample index `warmup_count`.

- **Ordered BB84:** Alice cycles H,V,R,L. Bob uses H/V for four trials, then R/L for four. All eight combinations occur every eight trials.
- **Randomized BB84:** Alice chooses one of four states and Bob independently chooses one of two bases every trial using operating-system cryptographic randomness. Realized choices are saved; a short random waveform is never repeated.

Both AO channels use finite buffered hardware generation, with regeneration disabled. Ctr0/PFI12 starts from the AO sample clock and emits the same finite number of delayed pulses. Both timing engines use the NI 100 MHz timebase with the same integer period. A separate writer supplies bounded blocks from the saved waveform while the acquisition worker drains PicoHarp FIFO. The final counter pulse must finish before AO values are zeroed.

PicoHarp runs in T3 with SYNC divider 1 and software start/stop. Recording begins before NI starts. Leading photons, warm-up events and trailing photons remain in the raw file; no quiet-laser start is required. SYNC rate/period is checked during runs long enough for the rate meter to settle. A matching rate does not prove index alignment.

The initial absence of SYNC is allowed for at most **0.5 seconds**, limited further
by the configured warm-up duration. The first clear SYNC flag ends this allowance
immediately. Persistent SYNC_LOST, or loss after recovery while NI is running,
aborts acquisition. No recovery before finite completion also fails the run.
After verified finite NI completion or during stopped-device draining, absence
of SYNC is logged as a boundary condition. FIFO/data-loss/system faults remain
fatal in every phase. All raw records and flags are retained, including boundary
flags (`flags_by_phase` in TTTR metadata). Host observation times and file offsets
are diagnostic only: they neither identify exact valid-event boundaries nor
establish trial zero. A completed commissioning recording is not validated key data.

If startup SYNC_LOST persists, check the BDL TRG OUT connection to PicoHarp SYNC
and the saved SYNC edge/threshold using the live alignment tool. Do not remove
the flag check or infer recovery solely from NI's generated pulse count.

## Saved files

Each timestamped folder under `data/bb84/ordered` or `data/bb84/random` contains:

| File | Content |
| --- | --- |
| `session.json` | Settings, timing, NI readbacks, rate checks, generated count, completion/cleanup state, unverified alignment |
| `sequence.json` | Trial/warm-up counts, state/voltage maps, randomness provenance and SHA256 hashes |
| `choices.npy` | Shape `(trials, 2)`, uint8: Alice state index (H,V,R,L = 0,1,2,3) and Bob basis index (HV,RL = 0,1) |
| `ao_waveform.npy` | Shape `(2, warmup + trials)`, float64 DAQ volts, including warm-up |
| `preview.csv` | First up to 1024 experimental trials with indices, Alice bits, states, Bob bases and voltages |
| `tttr/events.t3raw`, `tttr/metadata.json` | Ungated GenericT3 uint32 records and decoder/acquisition metadata |

Preparation-only folders contain sequence files and `requested_settings.json`, without acquisition files. Keep complete folders together. A 60-second run at 500 kHz uses approximately 540 MB for choices and AO commands, plus warm-up and raw T3. Generation, hashing and output streaming use bounded chunks. Free space is checked before array allocation; additional space is needed for raw records.

Stop/error retains partial files and marks acquisition incomplete. An intact sequence file alone does not mean all trials were emitted. The software stops Ctr0, stops AO, drains PicoHarp and attempts to zero both AOs. Cleanup failures invalidate completion. It never resets the entire NI device.

## Analyze a recording

Click **Analyze latest recording →**, or select **Analyze saved run** and browse to
the folder containing `session.json` (not `tttr`). Review the Analysis tab and click
Run. This action never opens hardware and ignores current acquisition voltages.
The figure opens automatically; PNG, PDF, SVG, per-setting CSV statistics, NPZ
histograms and `analysis.json` save under the same run's `analysis/<timestamp>/`.
Repeated analyses preserve earlier outputs.

For Ordered BB84, **leave the first-experimental-trial SYNC index blank** until an
independent timing reference has been established. The four panels show:

1. CH1/CH2 arrival distributions at native resolution, with the selected gate shaded.
2. CH1 / (CH1 + CH2) at each recorded SYNC phase modulo eight, with pointwise 95%
   Wilson counting intervals. These phases are not yet labeled as actual trials.
3. All eight possible phase alignments: numbers are measured CH1 percentages;
   colors show deviations from ideal 0%, 50% or 100% for each Alice/Bob pair.
4. Mean absolute deviation across the eight settings for each hypothesis, in
   percentage points. No best phase is automatically selected or declared verified.

The default gate is 50–60 ns; inspect arrival curves and adjust it. Default CH1
outcomes are provisional V at Bob HV and L at Bob RL, following the present
calibration convention; both are editable analysis assumptions, saved in the report.
Leave diagnostic range bounds blank to exclude the first `warmup_count + 0.5 s`
worth of recorded SYNC cycles and include the rest. This is a conservative display
cut, not an established warm-up boundary. Set explicit lower/exclusive upper SYNC
indices to compare portions of a run. If too little data remains, record longer.
No additional CH2 timing offset is applied.

An independently supplied first-experimental-trial SYNC index, with a reference
note, enables lookup of the saved, checksum-verified choices for either ordered
or randomized recordings. Warm-up and events outside the trial interval are then
excluded according to that supplied index. The figure instead shows per-setting
expected/measured percentages and a conditional detection matrix. A typed index
is still a user assumption: the software does not certify its experimental validity.
Randomized runs without an origin receive arrival/phase diagnostics only.

These are observed transmission/count-ratio comparisons, not reconstructed quantum
state fidelity, an accepted QBER, or a security calculation. Counting intervals do
not include drift, detector-efficiency differences, background, or alignment error.
Boundary SYNC flags remain visible in metadata; genuine data-loss/in-run SYNC errors
and incomplete recordings are rejected. All raw records are scanned in bounded chunks.

The redundant **Advanced: raw T3 preview** selector was removed. Its decoder remains
as shared supporting code, and its legacy command-line preview remains available.
That preview rejects any SYNC_LOST flag, whereas the new BB84 diagnostic understands
the explicitly logged startup/stop boundary flags and still labels timing unverified.

## Required next bench validation

A 100 kHz → 500–750 kHz preamble alone does not solve T3 alignment. T3 stores a
photon's SYNC count and microtime; it does not store individual SYNC timestamps or
the intervals between them. Overflow records extend the count, not elapsed time.
Sparse photons may reveal a statistical change but cannot certify the exact
transition pulse. Polling GetSyncPeriod or attaching host timestamps does not
restore that missing hardware timestamp. A T3 marker or T2 recording is needed;
switching from T2 to T3 creates a new acquisition and does not preserve a proved
index origin automatically. The application has not enabled a rate-step preamble.

The intended relationship is `NI sample index = warmup_count + trial_index`. **The offset to the recorded PicoHarp SYNC index remains unknown.** A first photon, software timestamp, rate match, discarded warm-up or a repeating pattern does not uniquely establish it.

Before downstream trial matching, demonstrate a common hardware reference (for example a correctly timed NI marker captured by PicoHarp), including its boundary convention, missing-pulse behavior and repeated-start consistency. Marker wiring/configuration is not implemented in this version. Save the validated offset and evidence before accepting detections as indexed protocol data. Do not infer trial zero from the first detection.

Every current session records `alignment_status: unverified`, `sync_origin: null`, and `eligible_for_key_processing: false`, even when all hardware generation completes. Confirming voltage labels does not override this. Reconciliation/privacy amplification and security analysis remain downstream responsibilities.

Start with short ordered runs and scope-check the warm-up boundary and final delayed pulse, then verify longer USB-buffered runs. Compare switched optical fidelity with the static baseline at the same rate. Use random acquisitions for accepted protocol data only after these checks and the origin test pass.
