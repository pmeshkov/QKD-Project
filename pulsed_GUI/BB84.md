# Pulse-by-pulse acquisition

Use **Repeating H-V-R-L** first, then **Random BB84** after the timing and optical tests. Both are available in the main launcher. These modes acquire commissioning data; neither establishes the absolute NI-to-PicoHarp trial origin yet.

## Controls

1. **Run:** select **Check settings**. Start with 1 second of experimental data and 1 second of warm-up using **500 kHz / 1200 ns**. The alternative scope-tested profile requests 750 kHz / 900 ns; integer timing realizes approximately 751,880 Hz. **Custom** unlocks rate and delay. Pulse width defaults to 100 ns.
2. **Voltages:** verify Alice H/V/R/L and Bob H/V and R/L targets. New profiles inherit voltages and PicoHarp inputs from the saved polarization form when available. Unassigned notebook entries use provisional opposite pairs 0/2 and 1/3; they do not prove physical labels. Confirm the physical states and Bob basis mapping experimentally before setting the confirmation to Yes. DAQ volts = target EOM volts / -20.
3. **PicoHarp:** review trigger modes, edges, thresholds, offsets, serial and binning. CH2 +4.5 ns is configured once in hardware; do not repeat that correction offline.
4. **Files:** choose the run directory and enter calibration/emitter notes.
5. **Prepare sequence only** saves the sequence without opening hardware. **Record** prepares a fresh sequence, then controls NI and PicoHarp. Preparing one sequence and pressing Record does not replay the prepared file.

Use NI external triggering for these modes. Close other AO/counter tools and UniHarp. Opening the form or using Check settings does not access instruments. The new finite streaming acquisition requires bench testing; the earlier scope test used a repeating waveform.

## What is generated

During warm-up, Alice holds H and Bob holds H/V. The experimental sequence begins at NI sample index `warmup_count`.

- **Repeating H-V-R-L:** Alice cycles H,V,R,L. Bob uses H/V for four trials, then R/L for four. All eight combinations occur every eight trials.
- **Random BB84:** Alice chooses one of four states and Bob independently chooses one of two bases every trial using operating-system cryptographic randomness. Realized choices are saved; a short random waveform is never repeated.

Both AO channels use finite buffered hardware generation, with regeneration disabled. Ctr0/PFI12 starts from the AO sample clock and emits the same finite number of delayed pulses. Both timing engines use the NI 100 MHz timebase with the same integer period. A separate writer supplies bounded blocks from the saved waveform while the acquisition worker drains PicoHarp FIFO. The final counter pulse must finish before AO values are zeroed.

PicoHarp runs in T3 with SYNC divider 1 and software start/stop. Recording begins before NI starts. Leading photons, warm-up events and trailing photons remain in the raw file; no quiet-laser start is required. SYNC rate/period is checked during runs long enough for the rate meter to settle. A matching rate does not prove index alignment.

## Saved files

Each timestamped folder under `data/bb84/ordered` or `data/bb84/random` contains:

| File | Content |
| --- | --- |
| `session.json` | Settings, timing, NI readbacks, rate checks, generated count, completion/cleanup state, unverified alignment |
| `sequence.json` | Trial/warm-up counts, state/voltage maps, randomness provenance and SHA256 hashes |
| `choices.npy` | Shape `(trials, 2)`, uint8: Alice state index (H,V,R,L = 0,1,2,3) and Bob basis index (HV,RL = 0,1) |
| `ao_waveform.npy` | Shape `(2, warmup + trials)`, float64 DAQ volts, including warm-up |
| `preview.csv` | First up to 1024 experimental trials with indices, Alice bits, states, Bob bases and voltages |
| `tttr/events.t3raw`, `tttr/metadata.json` | Ungated GenericT3 uint32 records and decoder/acquisition metadata |

Preparation-only folders contain sequence files and `requested_settings.json`, without acquisition files. Keep complete folders together. A 60-second run at 500 kHz uses approximately 540 MB for choices and AO commands, plus warm-up and raw T3. Generation, hashing and output streaming use bounded chunks. Free space is checked before array allocation; additional space is needed for raw records.

Stop/error retains partial files and marks acquisition incomplete. An intact sequence file alone does not mean all trials were emitted. The software stops Ctr0, stops AO, drains PicoHarp and attempts to zero both AOs. Cleanup failures invalidate completion. It never resets the entire NI device.

No trial-resolved plot, QBER or key is automatically produced in these modes. The sequence preview and session log support commissioning. Static arrival plots remain in Polarization matrix. The advanced raw T3 preview can inspect the `tttr` subfolder, but is not an aligned BB84 analysis.

## Required next bench validation

The intended relationship is `NI sample index = warmup_count + trial_index`. **The offset to the recorded PicoHarp SYNC index remains unknown.** A first photon, software timestamp, rate match, discarded warm-up or a repeating pattern does not uniquely establish it.

Before downstream trial matching, demonstrate a common hardware reference (for example a correctly timed NI marker captured by PicoHarp), including its boundary convention, missing-pulse behavior and repeated-start consistency. Marker wiring/configuration is not implemented in this version. Save the validated offset and evidence before accepting detections as indexed protocol data. Do not infer trial zero from the first detection.

Every current session records `alignment_status: unverified`, `sync_origin: null`, and `eligible_for_key_processing: false`, even when all hardware generation completes. Confirming voltage labels does not override this. Reconciliation/privacy amplification and security analysis remain downstream responsibilities.

Start with short ordered runs and scope-check the warm-up boundary and final delayed pulse, then verify longer USB-buffered runs. Compare switched optical fidelity with the static baseline at the same rate. Use random acquisitions for accepted protocol data only after these checks and the origin test pass.

The [NI X-Series manual](https://docs-be.ni.com/bundle/pcie-pxie-usb-63xx-features/raw/resource/enus/370784k.pdf) describes counter start routing and finite pulse generation. The [USB-6351 specifications](https://www.ni.com/docs/en-US/bundle/pcie-usb-6351-specs/page/specs.html) cover AO buffering/timing limits. [PH330Lib, sections 5.4 and 7.2](https://downloads.picoquant.com/manuals/PicoHarp330_DLL_Manual.pdf) documents software start/stop mode 6 and FIFO acquisition. Hardware route verification/readback happens before output; actual timing still needs scope confirmation.
