## Repeat the recording test

Use the same confirmed wiring/attenuation, laser at internal 2 MHz, and close
UniHarp. In a VS Code terminal at the repository root, using `niDaqENV`:

```powershell
python pulsed/ph330_acquire.py --config pulsed/ph330_g2_2mhz_10db.json --rates
python pulsed/ph330_acquire.py --config pulsed/ph330_g2_2mhz_10db.json --acquire --seconds 10 --preview
```

The supplied profile uses rising +300 mV on both detector inputs, falling
-500 mV on SYNC, and divider 1. These starting settings counted successfully
in this test; their timing quality has not been fully calibrated.

Change `--seconds 10` to `--seconds 60` for a longer recording. Ctrl+C marks
the saved prefix incomplete. Preview runs after acquisition, so it does not
compete with hardware reads. The terminal shows progress and the absolute
output path; it does not open a live plotting window.

Default storage is always the repository's `pulsed/runs/ph330/<UTC timestamp>/`,
independent of the current working directory. The directory contains raw data
and metadata plus these optional preview products:

- `preview.png`: detector rate traces, delays from SYNC, and raw CH2-minus-CH1
  coincidence counts across +/-2.5 us. Open in VS Code or an image viewer.
- `preview_summary.json`: byte-count check, decoded channel counts, overflow
  bookkeeping and preview coverage.
- `coincidences_preview.csv`: delay-bin centers (ns) and raw pair counts.

The preview processes at most the first 2 million records by default and
clearly reports whether it used a prefix. It checks the full file's byte count,
but does not claim to have decoded records beyond the preview limit. It does
not normalize g2 or fit an antibunching dip. Absence of a dip is not a recording
failure. Regenerate the preview without touching hardware:

```powershell
python pulsed/ph330_preview.py pulsed/runs/ph330/20260913T204909_211537Z
```

`--max-records` changes the offline preview cap (up to 10 million). A bounded
pair-count limit prevents excessive memory use; reduce the preview cap if it
is reached. Raw data always remain intact.

## Electrical inputs before count-rate testing

The PicoHarp timing inputs have 50-ohm termination and a normal operating range
of -1.5 to +1.5 V, with preferred pulse magnitudes 200-500 mV. Its manual explicitly
requires attenuation of TTL detector signals. Excelitas specifies about +2.2 V
into 50 ohms for the SPCM-AQRH-1X family. Direct TTL connections must be resolved
before measurement; verify any inline attenuators and actual amplitudes.

For orientation, a 10 dB matched pad would reduce a nominal 2.2 V pulse to about
0.70 V; 14 dB to about 0.44 V. These are calculations, not measured levels or a
requirement to purchase a particular component. Use suitable broadband 50-ohm
attenuators and measure the resulting signal. Do not use a bare BNC tee to feed
two 50-ohm inputs in parallel. Optical attenuation does not reduce TTL pulse height.

B&H's published BDL-SMN TRG OUT specification is a negative timing pulse, about
-1 V into 50 ohms. Confirm the actual unit/cable signal with a fast scope. This
does not override the experimenter's manufacturer email about low repetition rates.

Measure SYNC and each detector waveform at the intended tagger connection using
50-ohm scope termination, accounting for any attenuation. This instruction is
for BDL/SPCM signals, **not raw NI PFI12**, whose drive limit is different.
Select the leading edge and a threshold within the clean pulse excursion;
do not treat the installed UniHarp default INI files as measured settings.
For positive SPCM pulses use edge mode/rising edge; for a confirmed negative
TRG OUT pulse use edge mode/falling edge as the initial approach. CFD is also
supported by the script when a validated negative-pulse CFD setup is available.

## Operator commands

Close UniHarp or otherwise release its device before Python device access. Use
`niDaqENV`, as for the DAQ scripts. From the repository root:

```powershell
python pulsed/ph330.py
python pulsed/ph330.py --probe
```

The first command tests DLL loading only. The second opens/closes available
devices without initialization or acquisition. If the terminal chooses the
wrong Python, replace `python` with:

```powershell
& "C:\Users\nanometa\miniconda3\envs\niDaqENV\python.exe" pulsed/ph330.py --probe
```

Copy `ph330_g2.template.json` to `ph330_g2.local.json` and enter confirmed
trigger thresholds/polarities and any cable/attenuator details in `notes`.
The null fields intentionally fail validation; the template is not a runnable
calibration. Preserve the two arm labels. For CFD set `mode` to `cfd`, specify
negative `level_mv` and `zero_cross_mv` (-100..0); `edge` is unused in CFD mode.

```powershell
python pulsed/ph330_acquire.py --config pulsed/ph330_g2.local.json
python pulsed/ph330_acquire.py --config pulsed/ph330_g2.local.json --rates
```

The first validates offline. `--rates` opens and initializes T3 mode, applies
the profile and reports SYNC, every detector count rate and vendor warnings.
It changes device input settings, but does not start TTTR collection.

Check SYNC near 2 MHz and both detector rates. Verify each arm independently
by an appropriate optical block/unblock check; repeat readings after varying
threshold modestly within the measured clean pulse. Look for a stable count
plateau rather than a noise-sensitive threshold. Save the chosen settings and
scope observations. A good rate alone does not establish timing jitter or absence
of ringing-induced counts.

Then take a short pilot:

```powershell
python pulsed/ph330_acquire.py --config pulsed/ph330_g2.local.json --acquire --seconds 10
```

Only after reviewing that pilot, increase duration for usable coincidence
statistics. The acquisition uses T3, divider 1, internal PicoHarp timebase,
zero channel/histogram offsets, disabled hardware event filtering and markers,
and hardware CTC duration. The example binning code is 6; actual resolution is
queried and the full microtime range is checked against the 500 ns period.
It does not gate photons in hardware or perform a detector-to-SYNC histogram
in place of the required detector-to-detector correlation.

## Files and handoff to analysis

Each run creates a unique folder in `pulsed/runs/ph330` with:

- `events.t3raw`: headerless little-endian uint32 records, in received order.
- `metadata.json`: configuration, device/DLL identity, actual microtime
  resolution, measured SYNC period, pre/post count rates and warnings, flags,
  record count, elapsed time, completion/error status and host timestamps.

These files must stay together. The raw file is **not a PTU file** and must not
be renamed `.ptu` or passed directly to a PTU reader expecting a header.
The record format is GenericT3 (`0x00010307`) as used by PicoHarp 330, not the
PicoHarp 300 format. Use PicoQuant's GenericT3 decoder or an explicitly compatible
implementation with the JSON metadata. Overflow records extend the sync counter;
they are not lost photons. In contrast, FIFO-full, dropped-count, sync/ref-loss
and hardware/software-error flags cause acquisition failure.

The loop preserves trailing FIFO records and retries empty reads after CTC
completion. Interrupted/failed runs retain their saved prefix and are marked
incomplete. Do not use incomplete data silently for quantitative g2. A successful
capture is not itself a validated optical g2 measurement. USB/disk performance
at the actual count rate remains a bench test.

The analysis collaborator should first verify the two detector identities,
overflow handling and decay distributions. Cross-correlate detector arrival
times with both delay signs across several laser periods. At 2 MHz, side peaks
should be separated by about 500 ns; cable delays can shift the central peak.
Do not assume the middle array bin is zero delay, as the old CSV plotting script
does. Compare integrated central/side peak areas with consistent windows and
account for background/stability as appropriate. Preserve ungated raw events
for later temporal-gate studies. This is source characterization; no Alice
sequence is generated or inferred for this internally clocked run.
